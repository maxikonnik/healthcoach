# Распознавание анализов — план реализации

> **Для агентов:** ОБЯЗАТЕЛЬНЫЙ СУБ-НАВЫК: superpowers:subagent-driven-development. Шаги помечены `- [ ]`.

**Цель:** инструмент принимает большую часть реальных выгрузок и узнаёт в них показатели, а не отвергает документ целиком из-за слова, которого нет в словаре из восьми строк.

**Замер на начало работы** (77 файлов в `samples/`, прогон текущего кода):

| | |
|---|---|
| принято документов | **29 из 77** |
| отказ «шапка не называет колонки» | 14 |
| отказ «шапка не найдена» | 27 (из них ~15 — не таблицы: УЗИ, гастроскопия, рекомендации) |
| отказ «формат не поддерживается» | 7 (все — временные замки Office `~$…`) |
| строк разобрано | 689 |
| **сопоставлено с базой знаний** | **15** (ферритин, калий, кальций) |
| не сопоставлено | 674 строки, 248 различных названий |

**Подход:** сперва табло, которое считает эти числа само, — иначе «стало лучше» проверить нечем. Дальше по убыванию отдачи: словарь шапок, отсев служебных строк, честный отказ для не-таблиц, справочники показателей, и в конце — шапки с опечатками распознавания под подтверждение коуча.

**Стек:** Python 3.12, pdfplumber, macOS Vision, pytest. Новых зависимостей нет.

## Общие ограничения

- Каждое обращение к базе — внутри `with context.session() as repo:`.
- Инструмент не угадывает. Где догадка неизбежна — он показывает её коучу и ждёт подтверждения, а не решает молча.
- Числовую основу считает код.
- **Данные клиентов не попадают в репозиторий никогда.** `samples/` закрыт от системы контроля версий; тесты по нему помечены маркером `samples` и пропускаются, когда папки нет. Ни одно значение, ФИО, адрес или номер заказа из образцов не переносится в `knowledge/`, в тесты или в код. Лабораторные референсные интервалы персональными данными не являются и переносить их можно.
- Тестовые ФИО — выдуманные.
- Полный набор тестов зелёный на каждом коммите. База: **754 passed, 1 deselected**.

## Решения, принятые до начала

1. **Показатели завожу я, целевые коридоры — нет.** Файлы в `knowledge/references/` получают название, синонимы, единицы, синонимы единиц и лабораторный интервал. Раздел `целевые` остаётся пустым: это врачебное суждение партнёра, и придумывать его нельзя. Показатель без коридора всё равно узнаётся, попадает в динамику и в список «нет правила» — то есть в рабочий список коуча.
2. **Шапку с опечатками разбираем, но с подтверждением.** Неточное совпадение слова шапки не даёт молча разложить колонки: инструмент показывает свою догадку и ждёт согласия коуча.

### Task 1: Табло качества распознавания

**Файлы:**
- Создать: `src/healthcoach/intake/corpus.py`
- Создать: `tests/intake/test_corpus.py`
- Изменить: `README.md` — как посмотреть табло

**Интерфейс:**

```python
@dataclass(frozen=True)
class FileOutcome:
    name: str            # имя файла — только для локального отчёта
    accepted: bool
    refusal: str | None  # класс отказа: 'шапка-колонки' | 'шапка-не-найдена' | 'формат' | 'иное'
    rows: int
    unparsed: int
    resolved: int


@dataclass(frozen=True)
class CorpusReport:
    outcomes: tuple[FileOutcome, ...]
    accepted: int
    refused_by: Mapping[str, int]
    rows: int
    resolved: int
    unresolved_names: Mapping[str, int]  # название с бланка → сколько раз встретилось


def scan_corpus(folder: Path, references, engine) -> CorpusReport: ...
```

Файлы вида `~$*` (временные замки Office) пропускаются молча — это не документы.

**Тест (помечен маркером `samples`):** прогон по `samples/` даёт **не меньше** сегодняшних чисел — принято ≥ 29 документов, сопоставлено ≥ 15 строк. Пороги записаны в тесте константами с комментарием, что их поднимает каждая следующая задача плана; понижать их нельзя без отдельного решения. Отдельный тест на выдуманном крошечном корпусе (две-три строки в `tmp_path`) проверяет саму сборку отчёта и работает без `samples/`.

**Отчёт для человека:** `python -m healthcoach.intake.corpus` печатает таблицу и сводку. Печатает только имена файлов, числа и названия показателей — ни значений, ни строк с персональными данными.

### Task 2: Шапка таблицы понимается по словам, а не по четырём ролям

**Файлы:**
- Изменить: `src/healthcoach/intake/lab_table.py` — `_HEADER_WORDS`, `_find_header`
- Тест: `tests/intake/test_lab_table.py` (дополнить)

**Что не так сегодня.** Словарь знает сокращение «ед», но не знает слова **«Единицы»**: шапка «Исследование Результат Единицы Референсные Комментарий» отвергается целиком. Не знает «Ед.изм.», «Реф.», «пределы», «Комментарий», «Предыдущий». Из четырнадцати отказов десять — ровно эти пропуски.

**Два изменения:**

1. **Словарь пополняется** словами, встреченными в корпусе: `единицы`, `ед.изм`, `ед.изм.`, `изм`, `реф` → роль единиц/референса соответственно; `пределы`, `значения` — как продолжения роли референса; `комментарий`, `предыдущий`, `динамика` — как **известные, но не нужные** колонки (новая роль «прочее»). Токенизация должна одинаково понимать `Ед.изм.`, `Ед. изм.` и `Ед изм` — проверить, как `_header_word_roles` режет строку, и чинить там, а не плодить варианты в словаре.

2. **Требование меняется по смыслу.** Сегодня нужны все четыре роли, иначе отказ. Но бланк без колонки единиц — обычное дело: единицы стоят прямо в названии («Гемоглобин, г/л»). Отказ должен наступать не когда роли не хватает, а когда **колонку не удалось опознать**: неизвестное слово в шапке означает, что разбор не знает, что это за столбец, и вот тогда колонка встанет не на своё место. Новое правило: обязательны «название» и «значение»; каждая остальная колонка обязана быть опознана хоть какой-то ролью, включая «прочее»; отсутствие колонки единиц или референса — не повод для отказа.

**Тесты:** каждая из восьми шапок, встреченных в корпусе (взять из отчёта табло, они не персональные данные), разбирается или отвергается ровно по новому правилу; шапка без колонки единиц разбирается, единицы у строки пустые; шапка с неизвестным словом по-прежнему отвергается и называет это слово; колонка «Комментарий» не попадает ни в значение, ни в единицы. Мутация: вернуть требование всех четырёх ролей — тест про шапку без единиц падает.

**Табло:** поднять пороги в `tests/intake/test_corpus.py` по факту прогона.

- [ ] Тесты → RED → реализация → GREEN → полный набор → коммит `feat: шапка таблицы понимается по колонкам, а не по обязательным ролям`

### Task 3: Служебные строки не становятся показателями

**Файлы:**
- Изменить: `src/healthcoach/intake/lab_table.py` — `_SERVICE`
- Тест: `tests/intake/test_lab_table.py` (дополнить)

**Что не так.** В измерения попадают «Страница» (28 раз по корпусу), «№ заказа» (19), «ПЕЧАТЬ: …», «I триместр:», и — хуже всего — строки вида «Адрес пациента …» с настоящим адресом (19 раз). Адрес пациента сохраняется в базе как показатель. В отчёт он не уходит (маскировка текста с бланка это ловит), но в данных ему не место, и он засоряет экран нераспознанных строк.

`_SERVICE` уже существует и отсеивает `Дата исследования`, `Штрихкод`, `Материал`, `Вн.№` — расширить его, а не заводить второй механизм.

**Что отсеивать:** строки, начинающиеся с `Страница`, `№ заказа`, `Адрес`, `ПЕЧАТЬ:`, `Пациент`, `ФИО`, `Дата рождения`, `Врач`, `Организация`, а также строки-заголовки триместров (`I триместр:` и подобные — двоеточие в конце без значения). Список собрать по корпусу, не по фантазии; каждая позиция должна встречаться в отчёте табло.

**Осторожно:** отсев не должен съесть настоящий показатель. Правило — совпадение с начала строки и только для перечисленных служебных слов; ничего похожего на название анализа в списке быть не должно.

**Тесты:** каждая служебная строка из списка не даёт измерения; строка «Пациентка беременна» (выдуманная, начинается на «Пациент», но это не служебная строка) — проверить, что правило по слову целиком, а не по префиксу; настоящие показатели не отсеиваются. Мутация: убрать `Адрес` из списка — тест падает.

**Табло:** число строк уменьшится, доля сопоставленных вырастет; пороги обновить.

### Task 4: Документ, который не является таблицей анализов

**Файлы:**
- Изменить: `src/healthcoach/intake/lab_table.py` — сообщение при отсутствии шапки
- Изменить: `src/healthcoach/app/routes_documents.py` — как отказ показывается коучу
- Тест: `tests/intake/test_lab_table.py`, `tests/app/test_document_routes.py`

**Что не так.** Пятнадцать файлов корпуса — УЗИ, гастроскопия, биоимпеданс, рекомендации эндокринолога. Это не выгрузки анализов, и отказ от них правилен. Но сообщение «в выгрузке не найдена шапка таблицы: неизвестно, где значение, а где единицы» описывает внутреннюю неудачу разбора, а не то, что произошло: коуч приложил заключение УЗИ, а инструмент жалуется на колонки.

**Что сделать:** различить два случая. Если в документе нашлись строки, но ни одна не похожа на шапку таблицы — сказать прямо: это не похоже на таблицу анализов, инструмент принимает выгрузки лабораторий с таблицей показателей; заключения, протоколы и рекомендации сюда не загружаются. Если текста не нашлось вовсе (пустой PDF, нечитаемое фото) — сказать про это отдельно, потому что лечится оно иначе (переснять).

Сообщение адресовано коучу и должно объяснять, что делать дальше.

**Тесты:** документ со связным текстом без шапки даёт сообщение про «не таблица анализов»; документ без текста — про пустой документ; настоящая таблица по-прежнему разбирается; текст сообщения виден на экране среза после загрузки.

- [x] Тесты → RED → реализация → GREEN → полный набор → коммит `feat: честный отказ, когда документ не таблица анализов`

```yaml
показатели:

    название: Гемоглобин
    синонимы: [Гемоглобин, HGB, Hb, Гемоглобин (HGB)]   # все написания, встреченные в корпусе

    синонимы_единиц: [g/L, г/дл]                         # только встреченные, не выдуманные
```

**Раздел `целевые` не заполнять** — решение 1. Файл без целевых коридоров валиден: показатель узнаётся, единицы сверяются, динамика строится, а в находках он честно попадает в «нет правила в базе знаний» — то есть в рабочий список коуча на экране находок.

**Границы:** переносить только названия, единицы и лабораторные интервалы. Никаких значений пациентов, ФИО, адресов, номеров заказов. Если лабораторный интервал в корпусе разный у разных лабораторий — брать самый распространённый и не выдумывать компромисс; если расходятся сильно, интервал не указывать вовсе.

**Тесты:** каждый заведённый файл загружается `load_references` без ошибок; идентификаторы уникальны по всей папке; ни один синоним не повторяется у двух разных показателей (иначе `resolve_analyte` вернёт неоднозначность и покажет коучу выбор); у каждого показателя единицы непустые. Отдельный тест с маркером `samples`: доля сопоставленных строк по корпусу выросла — порог в табло поднят.

### Task 6: Шапка с опечатками распознавания — под подтверждение коуча

**Файлы:**
- Изменить: `src/healthcoach/intake/lab_table.py` — неточное совпадение слов шапки
- Изменить: `src/healthcoach/app/routes_documents.py`, `templates/snapshot.html` — экран подтверждения
- Тест: `tests/intake/test_lab_table.py`, `tests/app/test_document_routes.py`

**Что не так.** Четыре документа отвергнуты из-за опечаток распознавания в самой шапке: «Ел. изм.» вместо «Ед. изм.», «En. изм.», «Референскыю» вместо «Референсные». Словарь тут бессилен — нужно допускать неточное совпадение.

**Правило.** Слово шапки, не найденное точно, сравнивается с известными словами по расстоянию редактирования; совпадением считается расстояние 1 для слов до пяти букв и 2 для более длинных. Порог зафиксировать константой с объяснением. Неоднозначное сближение (слово одинаково близко к двум ролям) — не совпадение.

**Главное — это не проходит молча.** Документ, чья шапка опознана неточно, **не создаёт измерений сразу**. Загрузка показывает коучу: вот строка шапки как её прочитало распознавание, вот как инструмент понял колонки, вот первые разобранные строки. Кнопка «Да, колонки верные» импортирует; «Нет» — отменяет загрузку. Механизм временного файла для этого уже есть (`_discard_staging` в `routes_documents.py`) — использовать его, а не заводить второй.

Точно опознанная шапка подтверждения не требует — сегодняшний путь не меняется.

**Тесты:** «Ел. изм.» опознаётся как единицы, «Референскыю» как референс; слово, далёкое от всех известных, по-прежнему отвергается; при неточной шапке измерения не создаются до подтверждения; после подтверждения создаются; отказ не оставляет ни файла, ни строки документа; точная шапка импортируется без экрана подтверждения. Мутация: разрешить импорт без подтверждения — тест падает.

- [ ] Тесты → RED → реализация → GREEN → полный набор → коммит `feat: неточная шапка разбирается только с согласия коуча`

## Что дальше (за рамками плана)

- Оценка уверенности распознавания выбрасывается (`ocr.py`, `topCandidates_(1)`); спецификация обещала помечать сомнительные значения — не сделано.
- PDF без текстового слоя не отправляется в распознавание картинки; спецификация такой запасной путь обещала.
- Формат `.docx` и `.xlsx` не поддерживается. В корпусе таких файлов нет — только временные замки Office, — поэтому доказательств, что это нужно, пока нет.
- Инструмент не учится на правках коуча: перепривязать строку к другому показателю в интерфейсе нельзя вовсе, и что коуч поправил — нигде не сохраняется. Это отдельный разговор и, возможно, следующий план.
- Заключения (УЗИ, протоколы) отвергаются целиком. Они клинически полезны, но это не измерения — им нужна своя форма хранения.
