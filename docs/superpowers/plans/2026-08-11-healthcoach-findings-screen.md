# Экран находок — план реализации

> **Для агентов:** ОБЯЗАТЕЛЬНЫЙ СУБ-НАВЫК: superpowers:subagent-driven-development. Шаги помечены `- [ ]`.

**Цель:** вместо простыни неформатированного текста — страница, на которой видно положение каждого значения относительно целевого коридора и сразу заметно то, что требует внимания.

**Подход:** маршрут `/snapshots/{id}/findings` начинает отдавать HTML; текстовая выгрузка переезжает на `/snapshots/{id}/findings.txt` и остаётся дословно прежней — её удобно скопировать целиком. Геометрия шкалы считается отдельной чистой функцией: это единственное место с настоящей арифметикой, и шаблон не должен её знать.

**Стек:** Python 3.12, FastAPI, Jinja2, pytest. Никаких новых зависимостей, никакого JavaScript: шкала рисуется вложенными `<div>` с процентными ширинами.

## Общие ограничения

- Каждое обращение к базе — внутри `with context.session() as repo:`.
- Числовую основу считает код. Шаблон только раскладывает готовое.
- Экран предназначен коучу: заметки из базы знаний (`note_private`) здесь показываются. В клиентский PDF они по-прежнему не идут — этот файл не трогаем.
- Инструмент не угадывает: если шкалу честно не построить, её нет, а не «примерно такая».
- Данные клиентов не попадают в репозиторий; тестовые ФИО — выдуманные.
- Полный набор тестов зелёный на каждом коммите. База: **687 passed, 1 deselected**.

## Что нельзя сломать

- В разметке должны дословно сохраниться `пол {sex}` и `возраст {N}` — на них стоят тесты `test_findings_report_the_subject_they_were_computed_for` и `test_age_is_taken_at_the_snapshot_date_not_today`.
- Тест `test_findings_dump_blocks_derived_index_across_snapshots` требует, чтобы строки `2.5` не было **нигде** на странице — включая атрибуты и стили. Поэтому все проценты в разметке — целые числа. Это же требование и по смыслу: заблокированное значение не должно просочиться в вёрстку.
- Восемь существующих тестов проверяют подстроки в `.text`. Их тела не править: если подстрока пропала из HTML — виновата вёрстка, а не тест.

### Task 1: Геометрия шкалы

**Файлы:**
- Создать: `src/healthcoach/report/scale.py`
- Тест: `tests/report/test_scale.py`

**Интерфейс:**

```python
@dataclass(frozen=True)
class Scale:
    value_pct: int        # 0..100 — положение маркера
    target_from_pct: int  # 0..100 — левый край целевой полосы
    target_to_pct: int    # 0..100 — правый край
    value_outside: bool   # значение вышло за ось и прижато к краю
    axis_low: float       # подпись левого конца оси
    axis_high: float      # подпись правого конца


def scale_for(value: float | None, target: Interval | None,
              lab_range: Interval | None) -> Scale | None: ...
```

**Правила:**

1. Ось строится по конечным границам `target` и `lab_range`. Если различных конечных границ меньше двух — шкалы нет (`None`): рисовать её было бы выдумкой.
2. Ось расширяется на 8% размаха в каждую сторону, чтобы маркер у самой границы был виден.
3. Открытый интервал (`low` или `high` равен `None`) означает, что полоса доходит до соответствующего края оси — «от 60» это полоса от 60 вправо до конца.
4. Значение вне оси прижимается к краю, `value_outside = True`; шаблон покажет стрелку вместо точки. Растягивать ось до далёкого выброса нельзя — коридор схлопнется в невидимую полоску.
5. `value is None` → шкалы нет.
6. Все проценты — целые (`round`), в пределах 0..100.
7. Вырожденная ось (верх равен низу) → шкалы нет.

**Тесты:** значение внутри коридора — маркер между границами полосы; значение ниже коридора — маркер левее `target_from_pct`; значение много выше лабораторного интервала — `value_outside`, маркер ровно 100; открытый сверху коридор — полоса до правого края; открытый снизу — от левого; только `lab_range` без `target` — шкала есть, полоса совпадает с осью, если целевого коридора нет вовсе (или её нет — решить и закрепить тестом); одна конечная граница — `None`; `value is None` — `None`; все проценты целые при некруглых числах (проверить, что в выводе нет дробей).

- [ ] Тесты → RED → реализация → GREEN → полный набор → коммит `feat: геометрия шкалы находки`

### Task 2: Раскладка находок для экрана

**Файлы:**
- Создать: `src/healthcoach/report/findings_view.py`
- Тест: `tests/report/test_findings_view.py`

**Интерфейс:**

```python
@dataclass(frozen=True)
class Row:
    finding: Finding
    scale: Scale | None
    target_text: str      # «60–90», «от 60», «до 30», «—»
    lab_text: str
    value_text: str       # «18 нг/мл», «— » при отсутствии значения
    tone: str             # ok | warn | bad | muted — под существующие классы .tag


@dataclass(frozen=True)
class Group:
    title: str
    rows: tuple[Row, ...]


@dataclass(frozen=True)
class FindingsView:
    attention: Group      # требуют внимания (severity 0-1)
    normal: Group         # в норме (severity 3)
    unjudged: Group       # оценить не удалось (severity 4-5)
    questionnaire: Group  # шкалы опросника — отдельно, у них нет коридоров
    missing_rules: tuple[str, ...]  # названия показателей без правила в базе знаний


def build_view(findings: Iterable[Finding]) -> FindingsView: ...
```

**Правила:**

- Группировка — по существующей `_severity` из `scoring/findings.py`, не по новой копии правил. Если понадобится импорт приватной функции — сделать её публичной, а не дублировать.
- Порядок внутри группы сохраняется тот, что дала `collect_findings`.
- Находки опросника (`KIND_QUESTIONNAIRE`) идут в свою группу независимо от степени: у них нет ни коридора, ни единиц в привычном смысле, и мешать их с показателями крови значит сравнивать несравнимое. Внутри группы порядок тоже прежний.
- `missing_rules` собирает названия находок с `rule_missing` — это прямая подсказка, чем пополнить `knowledge/references/`; главное ограничение качества отчётов, и коуч должен видеть список.
- Форматирование интервалов — переиспользовать `_interval_text` из `report/pdf.py`, а не писать второе. Если для этого её надо сделать публичной — сделать.
- `tone`: severity 0-1 → `bad`; 3 → `ok`; 4-5 → `muted`. Для опросника — по той же severity степени.

**Тесты:** находка «дефицит» попадает в `attention` с тоном `bad`; «в целевом» — в `normal` с `ok`; «правило не задано» — в `unjudged` и в `missing_rules`; шкала опросника не попадает в `attention`, даже когда степень тяжёлая; порядок внутри группы совпадает с порядком `collect_findings`; пустые группы остаются пустыми, а не исчезают; интервалы форматируются той же функцией, что и в PDF (сравнить с ней в тесте).

- [ ] Тесты → RED → реализация → GREEN → полный набор → коммит `feat: раскладка находок по группам`

### Task 3: Страница

**Файлы:**
- Создать: `src/healthcoach/app/templates/findings.html`
- Изменить: `src/healthcoach/app/templates/base.html` — стили шкалы и карточки находки
- Изменить: `src/healthcoach/app/routes_snapshots.py` — маршрут отдаёт HTML, текстовая выгрузка переезжает
- Изменить: `src/healthcoach/app/templates/snapshot.html` — ссылка «Находки» ведёт на страницу, рядом ссылка «текстом»
- Тест: `tests/app/test_snapshot_routes.py` (дополнить)

**Маршруты:**
- `GET /snapshots/{id}/findings` — HTML-страница.
- `GET /snapshots/{id}/findings.txt` — прежняя текстовая выгрузка, дословно та же, что сейчас, `PlainTextResponse`. Общий сбор данных вынести в helper, чтобы два маршрута не разошлись: они обязаны показывать одни и те же находки.

**Страница:**
- Шапка: `<h1>Находки</h1>`, под ней строка «Срез {дата}, клиент {код} · Считано для: пол {sex}, возраст {N} на дату среза» (дословные подстроки сохранить), ссылка «Открыть текстом» на `.txt`, ссылка назад на срез.
- Группа «Требуют внимания» первой, с числом в заголовке. Каждая находка — блок: название, значение с единицами, статус плашкой `.tag`, под ними шкала, ниже мелким — целевой коридор, лабораторный интервал, дата анализа, заметка.
- Группы «В норме» и «Оценить не удалось» — внутри `<details>`, свёрнуты; в `<summary>` число. Это идиома, уже принятая в `snapshot.html` для нераспознанных строк.
- Группа «Шкалы опросника» — таблица: шкала, баллы, степень, «заполнено N из M» при `partial`. Плашка степени тем же `.tag`.
- Если находок нет вовсе — `<p class="muted">` с объяснением, что в находки идут только подтверждённые показатели.
- Показатель, чьё название пришло с бланка (`title_from_document`), помечается плашкой `.tag.muted` «с бланка» — коуч должен видеть, что текст не из базы знаний.
- Блок «Нет правила в базе знаний» со списком `missing_rules`, если он непуст, и одной строкой о том, что эти показатели останутся без оценки, пока правило не добавлено.

**Разметка шкалы** (без JavaScript, целые проценты):

```html
<div class="scale">
  <div class="scale-target" style="left:{{ s.target_from_pct }}%;width:{{ s.target_to_pct - s.target_from_pct }}%"></div>
  <div class="scale-mark{% if s.value_outside %} outside{% endif %}" style="left:{{ s.value_pct }}%"></div>
</div>
<div class="scale-ends"><span>{{ s.axis_low }}</span><span>{{ s.axis_high }}</span></div>
```

**Стили в `base.html`** (в тон существующим `.tag` и `.step`): `.scale` — полоса высотой около 0.5rem, светлый фон, `position: relative`; `.scale-target` — зелёная полоса `#e8f2e8` c рамкой `#9c9`, `position: absolute`; `.scale-mark` — тёмная вертикальная риска 2px, `position: absolute`, `transform: translateX(-50%)`; `.scale-mark.outside` — та же риска другим цветом (`#b91c1c`), без сдвига, чтобы прижаться к краю; `.scale-ends` — `display:flex; justify-content:space-between; font-size:.75rem; opacity:.6`; `.finding` — блок с отступом снизу; `.finding h3` — размер как у `h2`, без верхнего отступа.

**Тесты:** страница отдаёт `text/html` и содержит название показателя и его статус; текстовый маршрут отдаёт `text/plain` и то же содержимое, что раньше; на странице есть подстроки `пол м` и `возраст 41`; находка вне коридора попадает в «Требуют внимания», в норме — внутрь `<details>`; показатель без правила назван в блоке пропущенных правил; шкала не рисуется, когда её нет (нет `class="scale"` в блоке такой находки); заблокированный производный индекс не даёт `2.5` нигде на странице; ссылка «текстом» ведёт на `.txt`; экран среза ссылается на обе.

- [ ] Тесты → RED → реализация → GREEN → полный набор → коммит `feat: экран находок вместо текстовой простыни`

## Что дальше (за рамками плана)

- Шкала не показывает динамику: предыдущее значение того же показателя рядом с текущим было бы полезно, но это уже график, который есть в отчёте.
- Находки нельзя открыть с рабочего стола — только с экрана среза.
- Порядок внутри группы — по названию; сортировка по величине отклонения внутри «требуют внимания» может оказаться полезнее.
