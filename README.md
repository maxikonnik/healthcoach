# Health coaching — рабочий инструмент специалиста

Локальный инструмент для одного health coaching специалиста. Работает на вашей
машине: ни сервера, ни регистрации, ни хранения медицинских данных у третьих лиц.

Собирает запрос клиента и его анализы, сверяет показатели с вашими референсами,
собирает черновик отчёта и даёт вам его выправить и утвердить.

## Что нужно

- **macOS.** Распознавание фотографий бланков работает средствами системы.
  На Linux и Windows всё остальное работает, фотографии — нет.
- **[uv](https://docs.astral.sh/uv/)** — ставит Python и зависимости сам.
  Если его нет: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **Claude Code**, залогиненный под вашей подпиской — нужен только для сборки
  черновика. Проверить: `claude -p "привет"` должен ответить.
  Всё остальное работает и без него.

Ставить Python отдельно не нужно: `uv` подтянет нужную версию при первом запуске.

## Запуск

```bash
cd /Users/komo4ekk/Documents/Claude/healthcoach
uv run python -m healthcoach.app.main
```

Первый запуск займёт минуту — `uv` соберёт окружение. Дальше секунды.

Откройте **http://127.0.0.1:8765**

Остановить — `Ctrl+C` в том же окне терминала.

## Порядок работы

1. **Завести клиента.** Пол и дата рождения обязательны: почти каждый целевой
   коридор в базе знаний задан для пола и возраста, и без них отчёт считался бы
   для другого человека.

2. **Создать срез** — один заход клиента: анкета, документы, находки, отчёт.

3. **Отправить опросник.** На карточке клиента кнопка выдаёт HTML-файл. Отправьте
   его клиенту в мессенджере: он открывает файл в браузере, в том числе на
   телефоне, заполняет за несколько подходов — прогресс сохраняется — и присылает
   обратно скачанный JSON. Вы загружаете этот файл в срез.

4. **Приложить анализы.** PDF или фотографию. Показатели заполнятся сами;
   строки, которые разбор не понял, показываются текстом — их вписываете руками.

5. **Сверить каждый показатель.** Ничего не попадает в находки без вашего
   подтверждения. Строки, помеченные «фото», заслуживают особого внимания:
   распознавание путает единицы.

6. **Ввести запрос клиента** его словами и **вычитать** его перед отправкой.
   Экран покажет исходный текст и рядом тот, что уйдёт модели, с предложенной
   автоматической чисткой. Пока вы не утвердите вычитку, к модели не уйдёт
   ничего.

7. **Собрать черновик.** Восемь разделов, каждый помечен находками, на которых
   стоит. Это несколько минут: разделы собираются по одному.

   Если у клиента накопилось несколько срезов, черновик можно собрать сразу
   по нескольким. На карточке клиента отметьте галочками нужные срезы и
   нажмите «Собрать отчёт по выбранным». Отчёт всегда принадлежит самому
   свежему из отмеченных срезов — это его дата и его запрос клиента; остальные
   отмеченные срезы только расширяют показатели, которые видит интерпретация.
   Как именно они складываются — в разделе «Что стоит знать» ниже. Набор
   выбирается один раз: как только черновик утверждён, состав не переиграть
   — понадобится другой набор, собирайте новый отчёт.

8. **Выправить и утвердить.** После утверждения черновик заморожен: ни разделы,
   ни запрос больше не меняются — клиент должен получить то, что вы утвердили.

## Что показывают плашки

На рабочем столе — по клиенту, на срезе — по каждому шагу воронки. Обе плашки
читают одно и то же состояние, поэтому не расходятся между собой.

- **карточка не заполнена** — заполните пол и дату рождения на карточке клиента.
- **нет срезов** — создайте первый срез.
- **ожидаем данные клиента** — отправьте анкету и попросите анализы: пока в
  срезе нет ни ответов, ни показателей.
- **нужен запрос клиента** — введите запрос его словами на экране среза.
- **не сверено: N** — подтвердите N показателей на экране среза.
- **запрос не утверждён** — вычитайте запрос и утвердите его перед отправкой.
- **черновик ждёт утверждения** — просмотрите разделы черновика и утвердите.
- **черновик не собран** — соберите черновик из восьми разделов.
- **отчёт готов** — черновик утверждён, можно скачать PDF.
- **долг по прошлым срезам: N** — в N более ранних срезах этого клиента
  осталась незакрытая работа (несверенные показатели, неутверждённый запрос
  или черновик без утверждения). Откройте старый срез и доведите его до конца.

## Где лежат данные

| Что | Где |
|---|---|
| База: клиенты, срезы, показатели, ответы, черновики | `data/healthcoach.db` |
| Приложенные выгрузки лабораторий | `data/documents/` |
| Ваши референсы, опросник, справочник специалистов | `knowledge/` |

**Резервная копия — это копия папки `data/`.** Скопируйте её целиком; база
переносится вместе с файлом. Папка закрыта от системы контроля версий и никуда
не уходит.

Схема базы обновляется сама при запуске новой версии инструмента, одной
транзакцией: прерванное обновление откатывается целиком.

## База знаний

Всё в `knowledge/`, под контролем версий, правится вручную.

- `references/` — ваши целевые коридоры по показателям. **Сейчас здесь один
  показатель.** Пока вы не наполните эту папку, большинство строк из выгрузок
  будет приходить нераспознанными, а отчёт получится коротким. Это самое
  полезное, что можно сделать для качества отчётов.
- `questionnaire.yaml` — большой интегральный опросник, 24 блока, 544 вопроса.
- `specialists.yaml` — специальности и ваши доверенные врачи. **Врачи видны
  только вам**: в отчёт клиенту они не попадают никогда.

## Что инструмент принципиально не делает

Не угадывает. Если название показателя не распознано — покажет как есть, а не
подберёт похожее. Если единицы не сопоставлены — скажет об этом, а не сочтёт их
одинаковыми. Если в бланке `<0.60` — сохранит текст, а не превратит в 0.60.
Если шапка таблицы не называет все колонки — откажется от документа целиком,
вместо того чтобы разложить колонки наугад. Если отчёт собран по нескольким
срезам и составляющие производного индекса сданы в разные из них — индекс не
считается, а черновик называет причину; сложить мартовское значение с
августовским и выдать индекс, как будто оба сданы разом, было бы неправдой.

Числа считает код. Модель их трактует, но не вычисляет.

## Что стоит знать

- **Свободный текст клиента вычитываете вы.** Автоматическая чистка убирает
  имя, дату рождения, контакты и код клиента, но фразу вроде «работаю в школе
  № 1234» не поймает никакое правило.
- **Проверка на утечку ошибается в сторону отказа.** Если фамилия клиента
  совпадает с обычным словом — Кровин, Костин, Сахаров — она отвергнет текст,
  где это слово встречается, и сообщит, какая именно основа виновата.
- **Повторная загрузка того же файла** добавит показатели второй раз. Список
  приложенных документов виден на экране среза.
- **Отчёт по нескольким срезам сворачивает показатели, а не срезы.** Если один
  и тот же показатель сдан в двух отмеченных срезах, в находки идёт только
  самое свежее значение — более раннее не пропадает, а остаётся видно в
  графике динамики. Это касается только показателей из разных срезов: если
  один и тот же показатель встретился дважды на разных бланках внутри
  *одного* среза — обе строки в находках сохранятся, как и раньше. Показатель,
  который сдавался только в старом из отмеченных срезов, всё равно попадёт в
  отчёт — свежий срез его просто не отменяет.
- **Анкета не смешивается.** Берётся анкета самого свежего из отмеченных
  срезов, где она вообще заполнена. Складывать баллы по шкалам из анкет
  разных визитов было бы нечестно — вместо этого используется одна, целиком.
- **Целевой коридор — по возрасту на дату анализа, а не на дату отчёта.** Если
  клиенту исполнилось 40 между мартовским и августовским анализом, мартовское
  значение сверяется с коридором для 39 лет, а августовское — для 40, даже
  если отчёт собирается позже них обоих.
- **Даты в клиентском PDF появляются, только если они разные.** Пока все
  значения в отчёте одной даты, таблица показателей выглядит как раньше —
  шапка говорит «Срез от …». Как только значения сданы в разные дни, в
  таблице появляется колонка «Дата сдачи анализа», а шапка называет охват:
  «Анализы сданы с … по …» — клиенту должно быть видно, что за чем стоит, и
  что речь о датах сдачи крови, а не о дате, когда отчёт был сделан.
- **Колонку дат включает разнобой дат, а не число отмеченных срезов.** Один
  срез, в который вы вложили два бланка разных дат, тоже получит колонку и
  охват в шапке. Так честнее: отчёт, значения которого сданы в два разных
  дня, должен об этом сказать. Но учтите: PDF пересобирается при каждом
  скачивании, поэтому уже утверждённый отчёт со старыми срезами такого рода
  при повторной печати выйдет с другой титульной страницей, чем при первой
  выдаче.
- **PDF пересчитывается заново при каждом скачивании**, а не хранится как
  готовый файл. Значит, если вы позже поправите базу знаний или референс, уже
  выданный клиенту отчёт при повторном скачивании может показать другие числа
  — заморозка чисел на момент утверждения в план пока не входит, это
  следующий шаг, ещё не сделанный.
